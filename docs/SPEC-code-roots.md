# nimbrail を作者以外のマシンでも正しく入る形にする

## 目的

nimbrail は `~/.claude` のミラーとして作られており、`install.sh` は既に言語・ハンドオフ置き場・git ポリシーを聞く。しかし**コードを置くディレクトリが作者固有のまま**で、友人の環境では権限とサンドボックスが噛み合わない。しかもそれは**エラーにならない**ので気づけない。

この状態を、fork した人が自分のマシンに合わせて入れられる形にする。

## 動機となった実測

要点:

- テンプレート内の作者固有パスは **8 値**、すべて `~/Documents/GitHub` と `~/Developers` の 2 パス
- **`skills/almanac/SKILL.md:12` と `skills/synoptic/SKILL.md:18` が同じ 2 パスを本文に直書き** — 友人の環境では存在しないディレクトリを走査し、本人のリポジトリを見落とす。**静かに間違う**（synoptic は実装中に判明。実測の grep が出力を切っていて見落としていた）
- `enabledPlugins` が 4 プラグインを明示的に無効化する。ただし代替が無いのは `frontend-design` だけ（Figma は claude.ai コネクタ、Chrome は同梱スキル `claude-in-chrome` で触れる）

### 追補 — 同じ配列に無関係なエントリが同居している

2 回目の通読で判明。**接頭辞や配列全体で除去してはならない。**

```
Edit( / Write( / Read( で始まる規則: 9 本 → うち 3 本は ~/Documents/claude-shared
sandbox.filesystem.allowWrite: 16 本 → コードルートは 2 本だけ
  残り 14 本 = claude-shared, .gitconfig, ~/.claude/skills, .cargo, .rustup,
              .npm, .cache, pip, .pyenv, .nvm, .bun, .gradle, .m2
```

`allowWrite` の 14 本は README の Prerequisites が「配線済み」と謳うツールチェーン設定そのもの。これが D2 の形を決めた。

## 決定

### D1. 配布形態 = fork + 各自 install
リポジトリはあなたの設定のまま置き、**install 側に適応層を足す**。汎用 starter kit 化は**しない**。

### D2. テンプレートはコードルートを持たない。install が生成して足す
`config/settings.template.json` から**コードルート由来の 8 値を削除する**（allow の 6 規則と `allowWrite` の 2 エントリ）。install は確定したルートから同じ形を生成して**追加**する。

**除去処理を書かない**のがこの決定の要点。消す対象を見分ける必要が消えるので、追補が示した同居エントリを巻き込む事故が構造的に起こり得ない。F-3（0 件なら 1 つも書かない）も自明に満たせる。

**ロールバック原本は壊れない** — パスの原本は `~/.claude/shared-dirs.json` の `codeRoots` に移る。個人設定キー（`enabledPlugins` / `extraKnownMarketplaces` / `mcp__pencil`）はテンプレートに残り、install は触らない（D11）。

### D3. 衝突の解決は install の仕事ではない
live と repo が食い違ったとき、install は解決を試みず **`/barometer` に委ねる**。

### D4. コードルートは候補を探して提案する
ヒットを提示して確認、違えば手入力。**ホーム全体の走査はしない**。

### D5. 黙って間違えない
0 件で確定したらパス形の規則を**一つも書かず**に完了し、終了サマリで告げる。`cwd` からの推測で埋めることは**しない**。D16（非対話）・D18（例外系）にも適用する。

### D6. 対象読者 = 相談できる友人
v1 は install の振る舞いと `almanac` の修正に集中し、散文は矛盾する箇所だけ直す。

### D7. 候補探索の範囲と判定
- 固定 9 候補: `~/Developers` `~/Documents/GitHub` `~/src` `~/code` `~/repos` `~/projects` `~/ghq` `~/work` `~/dev`
- 候補と認めるのは **`.git` を持つディレクトリを直下に 1 つ以上含む**もの。候補自身がリポジトリである必要はない。深さ 1 のみ
- ヒットは**全部一覧提示、既定は全部採用**。番号で外す / 手入力で足す
- **候補が 1 件も無ければ、対話実行に限り手入力を 1 回だけ促す**。空 Enter なら 0 件（D5 の経路）

### D8. `--code-root` は反復指定、かつ置換
永続済みの `codeRoots` に**マージせず置き換える** — マージだと間違ったルートを消せず、書き込み権限が残り続けるため。

### D9. `--no-settings` が最優先
コードルートを聞かず、生成せず、永続化もしない。`--code-root` が同時に渡されたら「settings を書かないので無視した」と 1 行警告する。この経路では F-3 の空サマリも出さない。

### D10. 再実行は `codeRoots` の状態で決まる
- **1 件以上あれば黙って引き継ぐ**。変えたいときだけ `--code-root`
- **空または未設定なら聞く**（後からディレクトリを作った人が永久に閉じ込められない）
- 引き継いだルートに**存在しない、または読めない**ものがあれば 1 行警告。勝手に消さない
- **`--code-root` を渡しても `--yes` が無ければ live の settings は温存される。** そのときは「`codeRoots` は更新したが settings は温存した。反映するには `--yes`」と警告する — これが無いと、直したつもりで古い権限が残り続ける

### D11. install は個人設定を落とさない — 害が起きる経路で警告する
`--no-personal` フラグは**作らない**。**いかなる場合も除去しない**（無条件）。

警告を出すのは実際に live が書き換わる 2 経路:
- **live が存在しない初回 install**
- **`--yes` で live を置き換える再実行** — 確認なしで通す経路だからこそ、何が変わるかを告げる

通常の再実行（live 温存）では出さない。文面は粒度を分ける — `frontend-design` は「代替が無い」と名指し、`figma` / `chrome-devtools-mcp` は「別経路あり」と添え、`extraKnownMarketplaces` と `mcp__pencil` も列挙する。

### D12. `almanac` と `synoptic` は `codeRoots` を読む
- 参照先は `~/.claude/shared-dirs.json` の `codeRoots`。**両スキル本文**の 2 パス直書きは削除
- **アクティブなリポジトリ = 各ルートの直下にある、`.git` を持つディレクトリ**
- 空 / 未設定 / 不正 JSON / 配列でない値 → 走査せず 1 行報告し、**他の節の生成は続ける**（週次で無人実行されるため、打ち切りもクラッシュも最悪）
- 実行時にルートが消えている / 読めない → **そのルートだけ飛ばして 1 行報告**し、残りは走査する

### D13. 散文は 6 箇所直す
`README.md` / `README.ja.md` の「作者固有の値」節と `--no-settings` 節、`SECURITY.md`、`docs/windows.md`。

`--no-settings` 節（`README.md:102` / `README.ja.md:90`）も**触る** — 「強制の層はこのマシン依存」の例として書き込みルートを挙げているが、可変化後は成立しないため。なおこの行は `EDITOR` = WebStorm とも書いており、**PR #28 で `nano` に変わって以来すでに古い**。

### D14. `test-install.sh` に 15 ケース足す
複数ルート指定 / 0 件 / 個人設定の警告 / `--no-settings` / 生成 JSON の妥当性 / `codeRoots` の永続化 / 引き継ぎ時の警告 / パス正規化 / 走査範囲 / `--code-root` + `--yes` 無しの警告 / `--yes` × `codeRoots` 1 件以上 / 存在しないパスの確認 / 読めない候補の飛ばし / **`--no-settings` + `--code-root` の無視警告** / **テンプレートにコードルートが残っていないこと（F-11）**。

各ケースの見どころ:

- **0 件**: 「パス形の規則が無い」でも「テンプレートとバイト同一」でもなく、「**コードルート由来のエントリが 1 つも無い**」を assert する。前者だと正しい実装（claude-shared の 3 規則とツールチェーンの 14 本が残る）に対して落ち、後者だと `--shared-dir` を渡した友人のマシンで落ちる（置換後の値はテンプレートと違う）
- **個人設定**: 警告が出ること**かつ**どのキーも除去されていないこと
- **走査範囲**: 9 候補以外を stat しないこと
- **`--yes` × `codeRoots` 1 件以上**: F-1 の節 (3) が節 (4) に勝ち、既存の権限が消えないこと。ここが崩れると `--yes` 一発で全コードルート権限が消える

### D15. 存在しないパスは警告して確認を取る
`--code-root` に存在しないパスを渡されたら警告し、**yes が出たら採用**。弾かない。`--yes` および TTY 無しでは yes とみなす。

これは **F-1「フラグ指定時はどのルートを使うかを問わない」の唯一の例外**。問わないのは選択であって、渡されたパスが存在しないという事実確認は別。

### D16. 非対話 × ルート未指定
TTY が無い、または `--yes` が付いていて `--code-root` が無いとき、**探索した候補は採用しない** → 0 件として D5 の経路。終了サマリに「非対話のため候補 N 件を採用しなかった」と**見つけた候補を列挙**する。

D15 と主語が違う。**D15 は「渡されたパスの存在確認」、D16 は「探索で見つけた候補の採用」**。

### D17. `codeRoots` の永続化
確定したルートは必ず `~/.claude/shared-dirs.json` の `codeRoots` に書く（`--no-settings` を除く）。0 件のときは `[]` を書く — D10 により空は未設定と同義なので、次回の対話実行では再び聞かれる。

- **書き込みに失敗したらエラーで止める。** F-5 がこの書き込みに依存しているため、黙って成功を報告してはならない
- **install 時に同ファイルが不正 JSON なら、上書きせず中止する** — 既存のハンドオフ置き場の設定を失わないため

### D18. 例外系（install 側）
- **権限で読めない候補 → その 1 件だけ飛ばして探索は続行**し、飛ばした旨を出す。install 全体を止めない
- 永続ルートが読めなくなっていた場合も D10 の 1 行警告に含める

### D19. パスの正規化 — 順序が意味を持つ
**(0) 相対パスを cwd 基準で絶対化 → (1) `~` へ縮める → (2) 末尾スラッシュを落とす → (3) 重複と入れ子を除去（親のみ残す）** の順。

順序が要るのは、**シェルが `--code-root ~/src` を install に届く前に絶対パスへ展開する**ため。探索で得た `~/src` とフラグ由来の `/Users/bob/src` を先に揃えないと、入れ子・重複の判定が文字列比較で素通りし、二重に許可される。

`$HOME` の外にあるルート（`/Volumes/dev` など）は**絶対パスのまま**採用する。

**`) " \ | &` と改行を含むパスは弾いて警告する。** `)` は `Edit(<root>/**)` の形を壊し、`"` は JSON の文字列を閉じ、`\` は注入に使う awk の `-v` 代入がエスケープとして解釈する。

> **実装時の訂正**: `|` と `&` は当初 sed 置換の区切り・全マッチとして危険だったが、注入が awk になったこの経路では無害（[DESIGN-code-roots.md](DESIGN-code-roots.md)）。それでも拒否のままにしてあるのは、`--shared-dir` と**同じ検証関数を共用する**ため — 集合を割ると 2 つの検証がずれていく方が高くつく。

`permissions.allow` と `sandbox.filesystem.allowWrite` は**同一のルート文字列から**生成する（形は異なる — D20）。

### D20. 生成する形
1 ルートにつき 4 エントリ。allow に `Edit(<root>/**)` `Write(<root>/**)` `Read(<root>/**)`、`allowWrite` に `<root>`。`<root>` は D19 で正規化した同一の文字列。

### D21. live の `codeRoots` 作成は仕様外
「現状の 2 ルートを live の `shared-dirs.json` に先に入れておく」は 1 回限りの機械操作で、2026-08-16 に実施済み。機能でも受け入れ条件でもないので仕様には入れない。

## 非機能

- **走査範囲**: 固定 9 候補・深さ 1 のみ。9 候補以外を stat しないことを D14 のケースで確認する
- **非対話実行が壊れないこと**: **TTY が無い、または `--yes` が付いている**実行は、いかなるプロンプトも出さない（TTY があってフラグのみの実行は非対話ではない — F-9 の存在確認はそこで起こる）。F-8 が規定する中止条件（`shared-dirs.json` の不正 JSON・書き込み失敗）に当たらない限り、**終了コード 0 で終わる**。中止条件に当たった場合は非 0 で終わり理由を出力する — 黙って成功を報告しないことが優先される
- **既存 live settings を壊さないこと**: 既存の `~/.claude/settings.json` がある状態で再実行したとき、`--yes` を付けない限りそのファイルは変更されない

## スコープ外

- `cwd` からの推測でルートを埋める / ホーム全体の走査
- 汎用 starter kit 化（個人設定をテンプレートから外す）
