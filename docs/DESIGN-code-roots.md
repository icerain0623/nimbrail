# コードルート可変化 — 詳細設計

作者以外のマシンでも `install.sh` が正しく入るようにする変更の詳細設計。要件は petrichor の仕様書が持つ。ここは**どう作るか**だけ。

適用した `detail-design-jp.md` のセクション: **3(モジュール/処理設計)・4(インターフェース)・6(テスト設計)・7(タスク分解 — `tasks.md` は repo 外)**。
飛ばしたもの: **1(開発環境・規約 — 既に確立済み)・2(DB — 無い)・5(インフラ — 無い)**。

---

## 前提 — レンダリング経路の実体

設計判断の根拠なので先に書く。`install.sh:418-459` を読んで確定した事実:

1. `SETTINGS_SRC` は初期値がテンプレートのパス。置換が 1 つでもあれば `$CLAUDE_DIR/.settings.rendered.$$.json` へ sed で書き出し、そちらを使う
2. **一時ファイルは `$TMPDIR` ではなく `~/.claude` に置く。** サンドボックスが `$TMPDIR` への書き込みを拒否することがあるため(既存コードのコメントに明記)
3. `copy()` は `diff -q` で **レンダリング結果と live を比較**する。一致なら「✓ matches repo」、差があれば確認を出し、**既定は live を温存**

3 が冪等性の仕組みであり、同時にこの設計の最大の制約になる。

---

## 決定 1 — 注入は行挿入。jq は使わない

> **実装時の訂正（2026-08-16）**: 挿入の道具は sed ではなく **awk**。sed の置換文字列内の `\n` は **GNU 拡張**で、macOS の BSD sed は literal な `n` を書く。このキットは macOS と Linux の両方を対象にしているので使えない。awk は両方に存在し、**他のバイトを一切変えない**という肝心の性質は同じ。以下の「なぜ jq ではないか」はそのまま成立する。

コードルートは配列への**要素追加**なので、値の置換である既存の sed 群には素直に乗らない。仕様のリスク表は当初 jq を想定していたが、**採らない**。

**jq に通すとファイル全体が再整形される。** テンプレートは手書き整形で、jq の出力とは必ずバイト差が出る。すると `copy()` の `diff -q` が**既存インストール済みの全員で全面不一致**を報告し、既定の温存に落ちる。結果として**新しいコードルート規則が一度も適用されないまま install が成功を報告する** — この企画が消そうとしている「静かに間違う」失敗そのものを、実装手段が再生産する。

友人の初回 install は live が無いので無傷。壊れるのは既存ユーザーだけだが、その筆頭が作者本人。

### 挿入の形

アンカーは `config/settings.template.json` の 2 箇所。

| 配列 | アンカー行 | 挿入する形 |
|---|---|---|
| `permissions.allow` | `    "allow": [` | `      "Edit(<root>/**)",` `"Write(...)"` `"Read(...)"` |
| `sandbox.filesystem.allowWrite` | `      "allowWrite": [` | `        "<root>",` |

- **アンカー直後に挿入する。** 末尾に足すと直前要素へのカンマ追加が要り、最終要素の判定が絡む。先頭挿入なら常に `"...",` の形で済む
- インデントはアンカー行から算出せず、**上記の固定値**を使う。テンプレートの整形は既知で、変わったらテストが落ちる
- ルートの順序は**確定した配列の順**を保つ。ソートしないのは、`--code-root` で渡した順が利用者の意図だから。順序が安定していれば `copy()` の再実行も安定する

### 既存の sed 群との関係

`render_args` に**追加しない**。既存の 5 つは値の置換で、こちらは行の挿入。同じ配列に混ぜると、挿入した行に対して後続の置換が走る順序依存が生まれる(既存コードが `s|nano|vi|g` で踏みかけた罠と同型)。**挿入は置換の後に、独立した sed パスとして実行する。**

## 決定 2 — 拒否する文字

`) " \ | & ` と改行を含むパスは採用せず警告する(F-10)。

| 文字 | 壊れるもの |
|---|---|
| `)` | `Edit(<root>/**)` の閉じ括弧 |
| `\|` | sed の区切り文字 |
| `&` | sed の置換で「マッチ全体」を意味する |
| `\` | sed のエスケープ |
| `"` | JSON の文字列 |
| 改行 | 両方 |

`--shared-dir` が既に `" \ | & ` と改行を同じ理由で拒否している(`install.sh:198-202`)。そこに `)` を足した集合になるので、**検証関数は共用できる**。

## 処理設計 — コードルートの確定 (F-1)

5 節の**先勝ち**。上から評価し、最初に一致した節だけを適用する。

```
(1) --no-settings           → 探索も質問も生成も永続化もしない。--code-root 同時指定は無視して警告
(2) --code-root が 1 つ以上 → それを採用（どのルートを使うかは問わない）
(3) codeRoots が 1 件以上   → 質問せず引き継ぐ。探索しない
(4) TTY 無し or --yes       → 探索はするが採用しない → 0 件。見つけた候補は列挙する
(5) それ以外                → 探索して一覧提示、既定で全採用
                              候補ゼロなら手入力を 1 回だけ促す（プロンプトはこの節の内部にしか無い）
```

**節 (3) が (4) より先にあることが要。** 逆なら `install.sh --yes` が既存の `codeRoots` を無視して 0 件になり、`--yes` は live を置き換える唯一の経路なので**全コードルート権限が一発で消える**。`test-install.sh` にこのケースを置く理由がこれ。

例外系:

- 節 (2) で存在しないパス → 警告し、対話なら確認を取る。`--yes` / TTY 無しは yes とみなす
- 節 (5) の探索中、権限で読めない候補 → **その 1 件だけ飛ばして続行**し、飛ばした旨を出す
- 節 (3) で引き継いだルートが存在しない / 読めない → 1 行警告。**消さない**
- 全 `--code-root` が文字検証で弾かれた → 0 件として節 (4) と同じ終端に落ちる

## 処理設計 — 正規化 (F-10)

**順序が意味を持つ。**

```
(0) 相対パス → cwd 基準で絶対化
(1) $HOME 配下 → ~ 表記へ縮める（$HOME 外は絶対のまま）
(2) 末尾スラッシュを落とす
(3) 重複と入れ子を除去（入れ子は親のみ残す）
```

(1) が (3) より先でなければならないのは、**シェルが `--code-root ~/src` を install に届く前に絶対パスへ展開する**ため。探索由来の `~/src` とフラグ由来の絶対形（`$HOME` が展開された `…/src`）を先に揃えないと、(3) の文字列比較が素通りして二重に許可される。

既存の `tildify()` / `expand_tilde()`(`install.sh:156-158`)がそのまま (0)(1) に使える。

## 処理設計 — 永続化 (F-8)

`~/.claude/shared-dirs.json` の `codeRoots` のみを書き換え、`default` / `overrides` を含む他のキーを保存する。

**検査の順序が要:** 同ファイルの妥当性検査は **settings.json を書く前**に行う。後だと、不正 JSON で中止したときに live settings だけ置き換わって `codeRoots` が未永続の半端な状態が残る。

- 不正 JSON → 上書きも settings.json の書き込みもせず中止(非 0)
- 書き込み失敗 → エラーで終了(非 0)。F-5 がこの書き込みに依存するので、黙って成功を報告しない
- `codeRoots` が存在するが配列でない → 未設定として扱い警告

`read_shared_default()` が既に jq とフォールバックの二経路を持つ(`install.sh:161`)。**読みは jq、書きも jq** でよい — このファイルは install が所有していて `copy()` の比較対象ではないので、整形が変わっても誰も困らない。決定 1 の制約は `settings.json` にだけかかる。

### 自動化しないもの

- **ケース 9 の「9 候補以外を stat しない」は直接検証しない。** `strace` / `dtruss` は可搬でなく権限も要る。代わりに**囮ディレクトリ**(`~/Sites` にリポジトリを置く)を用意して**採用されないこと**を assert する。走査していないことの証明ではないが、走査範囲を広げた実装は必ずこれで落ちる
- 対話の見た目(一覧の並び、番号入力)は `forecast` の手動シナリオ側

### 既知の制約

`test-install.sh` は `${TMPDIR:-/tmp}` が書けないと **`SKIP` して exit 0** する。サンドボックス下では静かに素通りするので、**このスイートの結果はサンドボックス外での実行でのみ意味を持つ**。
